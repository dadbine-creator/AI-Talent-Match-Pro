Hiring tools decide who gets seen. It would be a strange irony to build one that some people can't use. So: everyone should be able to use AI Talent Match Pro — with a screen reader, a keyboard, voice control, or whatever way you access the web. This page is where we are on that, honestly.

Our commitment

Accessibility isn't a checkbox we tick before launch — it's part of how we build, and it's never finished. We're a small team, which means we can't claim perfection, but it also means feedback goes straight to the people writing the code.

What's in place today

  • Interactive elements carry descriptive labels for assistive technology
  • Keyboard navigation across the main flows — no mouse required
  • Visible focus states, so you always know where you are
  • Reduced-motion support: if your system says less animation, we listen
  • Semantic HTML — real headings, landmarks, and lists, not styled divs pretending

Where we're honest about gaps

Some things aren't there yet. Rather than hide them, here's the current list:

  • Some low-emphasis text doesn't yet meet our contrast target — we're working through it
  • Complex AI result visualizations may not yet read well with screen readers
  • Mobile works, but hasn't been through a full accessibility audit
  • Some dynamic AI animations still need ARIA live region support

How we test

Axe
Automated accessibility checks during development.
Lighthouse
Google's audit tool — 90+ accessibility score is our bar.
VoiceOver
Apple's screen reader, tested on macOS and iOS.
Keyboard only
Unplug the mouse and use the product — regularly.

Our response commitment: Accessibility feedback gets a reply within 5 business days. If something is blocking you from using the platform at all, we treat it as urgent and aim to respond the same day.

The standard we're aiming for

Our target is WCAG 2.1 Level AA. We're not claiming full conformance today — the gaps above are real — but every release moves us closer, and we review where we stand regularly.
